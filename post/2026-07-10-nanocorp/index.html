NanoCorp is a Hard Windows Active Directory machine featuring a realistic exploit chain that combines recent Windows vulnerabilities with Active Directory misconfigurations. The attack begins by exploiting CVE-2025-24071 to trigger an NTLM hash leakage using a malicious ZIP archive. After successfully cracking the hash, Active Directory enumeration reveals several misconfigured ACL permissions, enabling privilege escalation to the monitoring_svc account. This account, being a member of the Protected Users group, requires Kerberos authentication to establish WinRM access. Finally, exploiting CVE-2024-0670 within the Checkmk agent grants full NT AUTHORITY\SYSTEM privileges on the Domain Controller.

We initiate a fast, non-port-scanning ping sweep (-sn) without reverse DNS resolution (-n) to verify host availability. The target responds to the ICMP echo requests, confirming it is active and reachable on the network.

Technical Note: The default Time-to-Live (TTL) value for Windows operating systems is 128. If the received packet displays a TTL of 127, it indicates that the packet has traversed exactly one router hop (such as your HackTheBox VPN gateway), decrementing the TTL by 1 (128 - 1 = 127). By contrast, a Linux-based system typically has a default TTL of 64, which would yield a TTL of approximately 63 after a single hop.

Local DNS Configuration (/etc/hosts)

To ensure proper routing for the newly discovered virtual hosts, we update our local /etc/hosts file. Key Outcome

The Domain Controller’s Key Distribution Center (KDC) validates our credentials and returns a valid TGT. The ticket is successfully saved locally as web_svc.ccache, allowing us to authenticate to other Kerberos-enabled domain services via pass-the-ticket (PtT) without needing to supply the plaintext password again.

Injecting the Kerberos Ticket (KRB5CCNAME)

To utilize our newly acquired Ticket Granting Ticket (TGT) with Impacket tools and other network utilities, we must load it into our current terminal session’s memory. This is done by exporting the path of our .ccache file to the KRB5CCNAME environment variable:

Export KRB5CCNAME 

1

export KRB5CCNAME=web_svc.ccache

By setting this variable, any subsequently executed Kerberos-aware tools (such as secretsdump.py, psexec.py, or nxc) will automatically read the ticket from web_svc.ccache instead of prompting for a password or NTLM hash, enabling seamless Pass-the-Ticket (PtT) authentication across the Active Directory domain.

Exploiting Checkmk MSI (Arbitrary File Execution)

The Domain Controller has Checkmk monitoring software installed. When a Windows Installer repair operation (msiexec /fa) is triggered, the engine runs under the NT AUTHORITY\SYSTEM context. During this routine, the installer attempts to execute temporary configuration batch files (.cmd) in the public C:\Windows\Temp\ directory. These files are dynamically named using the PID of the active installation process.

By leveraging a PID Seeding / Pre-creation attack, we can pre-create a wide range of batch files corresponding to potential future PIDs. When the installer executes and matches one of our seeded paths, it runs our payload with SYSTEM privileges.
